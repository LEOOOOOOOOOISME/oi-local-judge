一、项目概况
------------

Windows 局域网 OI 评测系统：

- 桌面壳：Electron（开发沙箱内无法启动，待目标机验证）
- 服务端：Fastify 5 + Node 24 + node:sqlite（WAL）
- 前端：React 18 + Vite + Ant Design 5 + TanStack Query
- 原生执行器：ojrunner.exe（单进程 Job Object 沙箱）
                ojinteract.exe（双进程交互管道）
- 数据目录：默认仓库下 runtime/（gitignored）；OIJ_DATA_DIR 可覆盖
- 目标环境：Windows 10/11 x64，4C/8G，300 在线，50 并发提交

五、已确认但尚未实现的下一阶段需求
----------------------------------

以下为最近一轮需求讨论的决策，代码尚未实现：

1. 比赛批量正式导入
   - 批量导入与赛中网页提交共同构成正式赛时榜
   - 批量导入按三种模式作用于正式格子：
     覆盖：只更新批次出现的 学生×题目 格子
     合并：逐格取较高分
     仅补缺：只填空格
   - 先落草稿，管理员预览后发布；发布前不影响正式榜
   - 未注册用户名跳过并报告
   - 参赛名单任意时间追加导入；未知用户跳过并报告
   - 参赛者移除后从正式榜和订正榜隐藏，成绩保留
   - 正式榜和批量榜单统一数据源，批次完成后跳转/展示比赛正式榜

2. 排名引擎
   - 支持 OI/IOI/ACM/CF/自定义规则
   - 并列、罚时、封榜、可见性可配置
   - 内置策略 + 声明式配置 + 开发者 TS 插件接口
   - 应用内 /help + 仓库 docs 帮助文档
   - 当前系统实际只有 OI 总分榜；ACM 罚时、CF 规则、插件接口均未实现

3. 独立订正页
   - 比赛结束后自动永久开放订正
   - 只有比赛结束后的提交算订正，且提交人必须是参赛者
   - 订正页公开、独立路由
   - 每题取 max(赛中官方分, 赛后最高分)
   - 订正榜固定 OI 总分制；与官方榜分开存储、分开展示
   - 比赛页赛后自动出现“订正提交”入口
   - 当前未实现订正阶段、订正页、官方/订正分离存储

4. 完整 CF hack（本期决策为完整实现，但尚未开始）
   - 仅赛中网页提交可被 hack
   - 判定：用题目 std 生成预期输出，再跑目标程序 + checker
   - 成功后测试数据默认仅存在本场比赛，管理员可手动晋升为正式测试点
   - 锁题后本人不能再提交，只能 hack；不可解锁（管理员可审计强制解锁）
   - 完整 CF 计分公式（题分 + 剩余时间 + 成功/失败）
   - 赛中 + 赛后开放窗口，可配置
   - 锁定题目后可看同题其他提交源码
   - 被 hack 后标记 HACKED，从正式分剔除并重算
   - 当前无 hack 数据模型、源码可见性、测试提交、重测、HACKED 状态

5. 客观题/提交答案题批量导入
   - 已决定统一使用 answers.json

六、风险与注意事项
------------------

1. 完整 hack 是独立子系统，不是榜单附属功能；涉及源码隐私、测试数据安全、
   历史重测、排名重算，风险最高。
2. 排名引擎改造会影响现有 OI 榜单、封榜、班级统计、大屏和 CSV，需要迁移与回归。
3. 正式分/订正分分开存储后，比赛页、订正页、批量页、班级统计必须统一口径。
4. 批量 answers.json 需要为客观题、提交答案题分别定义字段与校验。
5. 当前测试偶发并发抖动（复跑通过），正式发布前建议固定测试槽位/超时。
6. Electron 尚未在目标 Windows 机器启动验证。
7. runtime 当前含演示/测试数据，正式部署前应清理或新建数据目录。

九、结论
--------

比赛、榜单、批量评测、社区、用户与审计均可运行，测试与性能基准通过。
