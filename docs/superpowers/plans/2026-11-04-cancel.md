# Judge Cancellation Plan

**Goal:** 管理员/比赛管理员可取消排队或运行中的评测；运行器进程被终止；状态为 `canceled`，不会变成 SE/WA；可重测恢复。

## Design

- `submissions.status` 新增 `canceled`；`judge_tasks.status` 新增 `canceled`。
- `judge/cancellation.ts`：
  - `registerCancellation(submissionId): AbortController`
  - `abortSubmission(submissionId): boolean`
  - `releaseCancellation(submissionId)`
  - `isCancellationAborted(submissionId)`
- Scheduler 每个任务注册 controller，传给 `judgeSubmission({ signal })`；`finally` 释放。
- `runSandboxed` 接受 `signal`，传给 `execFile`；中止时抛 `AbortError`。
- Pipeline：
  - 每个 testcase 前检查 `signal.aborted`；
  - `judgeTestcase` 接受 signal；
  - 捕获 `AbortError` → `cancelSubmissionState`（不是 markSubmissionFailed）。
- 取消服务：
  - queued：task=`canceled`，submission=`canceled`；
  - running/compiling：submission=`canceled`，abort；scheduler 完成时 task=`canceled`；
  - finished/failed：409 `CANNOT_CANCEL`；
  - 任务不存在/无权：404/403。
- `rejudgeSubmission` 允许 canceled 重新入队（重置状态）。
- API：`POST /api/admin/submissions/:id/cancel`；admin/setter/contestmanager。
- UI：提交详情页管理员/比赛管理员显示“取消评测”；确认后调用，显示 canceled。
- 测试：queued cancel、running cancel（sleep 程序 + 延迟）、finished 409、非管理员 403、重测取消的提交。
