# AI 提示词库：std / generator / validator / checker

> 适用版本：1.1+
> 用法：复制提示词 → 填入题目信息 → 交给任意 AI → 把返回的代码粘回资产编辑器 → 编译、试跑、审核。
> **AI 生成代码不可直接发布**。必须通过编译、样例、生成数据、validator 和人工审核。

---

## 0. 通用规则

### 0.1 给 AI 的输入

至少提供：

- 题面（输入/输出格式）
- 数据范围
- 子任务/部分分
- 样例
- 时限/内存
- 编译器标准（C++17）
- 是否需要 testlib

### 0.2 对 AI 输出的要求

- 只输出一个代码块
- 不解释、不写测试、不写 main 之外的额外文件
- 不使用文件 IO、网络、系统命令
- 不使用未定义行为
- 代码必须能在 `g++ -O2 -std=c++17` 下编译
- 生成器必须确定性、可复现

### 0.3 人工检查清单

- [ ] 能编译
- [ ] 样例通过
- [ ] 边界数据通过
- [ ] 大数据不超时/不爆内存
- [ ] 没有随机/时间/文件/网络
- [ ] 没有未定义行为
- [ ] 输出格式与题面完全一致
- [ ] 生成器同 seed 可复现

## 1. std 提示词（传统/文件 IO）

```text
你是一位经验丰富的 OI 命题人，请为下面这道题生成一份 C++17 标准程序（std）。

【题目】
{{题面：背景、输入格式、输出格式、数据范围、子任务、样例}}

【限制】
- 时间限制：{{time_ms}} ms
- 内存限制：{{memory_mb}} MB
- 编译器：g++ -O2 -std=c++17
- 输入输出：标准输入/标准输出（不要文件 IO）

【要求】
1. 只输出一个 C++ 代码块，不要解释。
2. 使用标准输入输出；不要读写文件、不要联网、不要调用 system/popen。
3. 不使用随机数、时间、未定义行为；不要使用 VLA。
4. 注意 long long / __int128 溢出；注意负数、0、n=1、空输入等边界。
5. 时间复杂度必须满足题面约束；空间复杂度也必须满足内存限制。
6. 递归深度必须可控；如果可能爆栈，改成迭代。
7. 输出格式必须与题面完全一致（空格、换行、保留小数位数）。
8. 如果题目有多解，输出任意合法解，并确保符合 checker 的要求。
9. 代码必须能在 g++ -O2 -std=c++17 下编译通过。

【自检】
- 样例是否通过？
- 边界是否处理？
- 是否会溢出？
- 复杂度是否达标？
```

### 1.1 文件 IO 版本补充

```text
输入文件：{{input_file}}
输出文件：{{output_file}}
请使用 freopen 或 ifstream/ofstream，并在 main 开头打开文件；不要同时读写标准输入输出。
```

## 2. generator 提示词（testlib）

```text
你是一位 OI 出题人，请为下面这道题生成一个 testlib.h 数据生成器 generator.cpp。

【题目】
{{题面：输入格式、输出格式、数据范围、子任务}}

【数据计划】
- 子任务：{{subtask_list}}
- 每组测试点数量：{{counts}}
- 需要覆盖的边界：{{edge_cases}}
- 单点生成时间上限：{{gen_time_ms}} ms
- 输出大小上限：{{output_mb}} MB

【硬性要求】
1. 只输出一个 C++ 代码块，不要解释。
2. 必须包含 #include "testlib.h"。
3. 必须使用 registerGen(argc, argv, 1)。
4. 必须支持参数：
   --seed=<int>
   --group=<string>
   --index=<int>
   以及题目需要的 --n=...、--m=... 等参数。
5. 只能使用 rnd 生成随机数；禁止 rand()、random_device、time()、chrono。
6. 只写 stdout；不要写文件、不要联网、不要调用系统命令。
7. 同一 seed + 同一参数必须产生完全相同的输出。
8. 输出必须满足题面的格式和范围；不要输出多余空格/空行。
9. 生成时间必须可控；不要写可能死循环的构造。
10. 代码必须能在 g++ -O2 -std=c++17 下编译通过。

【子任务实现】
- group=1：...
- group=2：...
- group=3：...
每个 group 的输出范围必须严格符合对应子任务约束。

【自检】
- 同 seed 跑两次是否完全一样？
- n=1、最小值、最大值是否覆盖？
- 是否会输出超出范围的值？
- 是否会生成空文件或超大文件？
```

### 2.1 generator 模板

```cpp
#include "testlib.h"
#include <bits/stdc++.h>
using namespace std;

int main(int argc, char* argv[]) {
    registerGen(argc, argv, 1);

    int n = opt<int>("n", 10);
    int maxV = opt<int>("max-v", 1000000000);
    int group = opt<int>("group-id", 1);

    if (group == 1) n = rnd.next(1, 10);
    else if (group == 2) n = rnd.next(11, 1000);

    println(n);
    vector<int> a(n);
    for (int i = 0; i < n; ++i) a[i] = rnd.next(1, maxV);
    println(a);
    return 0;
}
```

## 3. validator 提示词（testlib）

```text
你是一位 OI 出题人，请为下面这道题生成 testlib.h 输入校验器 validator.cpp。

【题目输入格式】
{{input_format}}

【数据范围】
{{constraints}}

【要求】
1. 只输出一个 C++ 代码块。
2. 使用 registerValidation(argc, argv)。
3. 使用 inf 读取输入；必须读完所有 token，不能留下未读数据。
4. 检查：
   - n/m 的范围
   - 每个元素的范围
   - 行数/列数
   - 特殊约束（互不相同、连通、无环、升序等）
   - 输入末尾没有多余内容
5. 违规时使用 quitf(_fail, "...")，信息必须包含具体原因和值。
6. 不要输出任何内容到 stdout；不要写文件。
7. 代码必须能在 g++ -O2 -std=c++17 下编译通过。

【自检】
- 最小合法输入是否通过？
- 最大合法输入是否通过？
- 越界/缺行/多行/多余 token 是否被拒绝？
```

## 4. brute 提示词（对拍）

```text
你是一位 OI 选手，请为下面这道题生成一份 C++17 暴力程序 brute.cpp，用于和 std 对拍。

【题目】
{{题面}}

【要求】
1. 只输出一个 C++ 代码块。
2. 标准输入/输出；不读写文件、不联网。
3. 暴力算法必须正确，允许比 std 慢；但必须在题目约束下可运行。
4. 使用 long long 防溢出；处理边界。
5. 复杂度不超过 O({{brute_complexity}})，确保小数据可跑。
6. 代码必须能在 g++ -O2 -std=c++17 下编译通过。
```

## 5. checker 提示词（testlib SPJ）

```text
你是一位 OI 出题人，请为下面这道题生成 testlib.h 特判器 checker.cpp。

【题目】
{{题面}}

【判定规则】
{{judge_rules：多解、浮点误差、部分分、构造合法性等}}

【要求】
1. 只输出一个 C++ 代码块。
2. 使用 registerTestlibCmd(argc, argv)。
3. 使用 inf / ouf / ans 读取输入、选手输出、标准答案。
4. 必须读完 ouf；多余输出按规则判 WA/PE。
5. 使用 quitf(_ok/_wa/_pe/_dirt) 或 quitp(score, ...) 给出结果。
6. 部分分必须是 0..1 的比例（如果需要按 0..100，请说明）。
7. 所有判定信息必须可读，包含具体原因。
8. 代码必须能在 g++ -O2 -std=c++17 下编译通过。
```

## 6. 修复提示词

当 AI 生成的代码编译失败、WA、TLE 时，复制下面模板：

```text
下面是我用于 OI 题目的 C++17 代码和失败信息。请修复它，并只输出修复后的完整代码块。

【题目】
{{题面}}

【代码】
{{code}}

【失败信息】
{{compile_error / wrong_answer / tle / re}}

【要求】
1. 只输出一个 C++ 代码块，不要解释。
2. 保持标准输入/输出（或题目要求的文件 IO）。
3. 不要引入随机、时间、文件、网络。
4. 修复后必须能通过样例和边界。
5. 如果无法修复，输出一行 `CANNOT_FIX: 原因`。
```

## 7. 常见 AI 错误

| 错误 | 表现 | 处理 |
|---|---|---|
| 用了 `rand()` | 数据不可复现 | 改 `rnd` |
| 用了 `time(0)` | 每次不同 | 删除 |
| 文件 IO | 与题型不符 | 改标准 IO |
| 输出多余空格 | PE/WA | 按题面格式 |
| `int` 溢出 | WA | 改 `long long` |
| 复杂度错误 | TLE | 重写算法 |
| 递归爆栈 | RE | 改迭代 |
| 生成器死循环 | 生成超时 | 加边界/次数限制 |
| 没读完输入 | validator 误判 | 读完全部 token |
| 多解判错 | checker 错误 | 按规则重写 |
