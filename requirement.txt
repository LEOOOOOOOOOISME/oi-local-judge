0.2 术语
    OI      信息学奥林匹克竞赛
    SPJ     Special Judge，特判/自定义校验器

    Subtask 子任务；一组测试点聚合为一个子任务
    AC/WA/TLE/MLE/RE/CE/OLE/PE/PC/SK/SE  评测状态（见附录 A）

    选手    参赛学生，使用浏览器访问
    出题人  创建题目、配置数据、编写 SPJ 的管理者
    管理员  拥有系统级权限的角色
    题包    可导入导出的题目集合（含数据、配置、辅助程序）
    题库    系统内所有题目的集合

    P1 = 二期交付，显著提升赛事完整度
    P2 = 三期交付，锦上添花

1. 产品定位与核心场景
--------------------------------------------------------------------------------
1.1 定位
    一套"开箱即用"的 Windows 桌面评测系统：老师在自己电脑上出题、配数据、办比赛；
    学生用浏览器通过局域网访问，登录后看题、写代码、提交、看评测与榜单。
    核心价值：本地化、零公网依赖、数据不出机房、赛事全流程可控。

1.2 三种使用形态（同一套程序）
    A. 单机个人/教学：本机打开程序，手动选题、提交代码、即时评测，用于练习与讲题。
    B. 单机多选手：机房一台主机开程序，多台学生机浏览器访问，统一提交排队评测。
    C. 局域网托管：主机承担"评测机 + 网页服务"双重角色，可无人值守运行一整天。

1.3 典型赛事流程（端到端）
    安装 → 配置编译器/端口/数据目录 → 建题（题面+数据+SPJ+std+validator）
    → 校验数据 → 组卷建赛 → 导入/注册选手账号 → 开赛 → 选手答题提交
    → 队列评测 → 实时榜单（可封榜）→ 赛时答疑/公告 → 结束结算
    → 成绩分析/导出 → 备份归档。

1.4 成功标准（一句话）
    一位不熟悉命令行的老师，能在 1 小时内完成"装好 → 建 3 道题 → 导 50 个账号
    → 开一场 2 小时比赛 → 导出成绩"；500 人规模下网页不卡、评测不堵、断网可恢复。

1.5 洛谷功能对标清单（"所有实现都要考虑洛谷"的落地解释）
    题库列表（难度/标签/通过率/搜索）         → FR-PRB-010/020
    题目页（题面/样例/提交/我的记录/题解）    → FR-WEB-001、FR-COM-003
    评测记录列表与详情（测试点/代码/重测）    → FR-JDG-040~045
    个人中心（通过题、提交、比赛、排名）      → FR-RNK-007、FR-ACC-006
    比赛页（倒计时/公告/题目/答疑/榜单）      → FR-CST-011/012、FR-RNK-001~005
    客观题（选择/判断）与混合组卷             → FR-PRB-005、FR-CST-003、FR-JDG-036
    讨论区/题解/私信（权限与审核）            → FR-COM-001~010
    榜单大屏与赛后分析                        → FR-RNK-005/006/010
    说明：只对标信息架构与功能语义，不复制洛谷的文案、视觉资产与专有数据。

2. 角色与权限
--------------------------------------------------------------------------------
2.1 角色
    - 系统管理员（Admin）：所有权限，含系统设置、备份恢复、审计、角色分配。
    - 出题人（Setter）：建题/改题/配数据/写 SPJ/导入题包；可被授予比赛管理权。
    - 比赛管理员（Contest Manager）：开赛、延时、封榜、重测、公告、选手管控。
    - 选手（Contestant）：看题、提交、看自己的记录、答疑、赛后讨论。
    - 访客（Guest，可选）：只读榜单/题面（按比赛配置）。

2.2 权限点（默认配置，全部可单独授予/回收，支持"角色 + 例外"）
    账号类  : 查看用户 / 创建用户 / 导入用户 / 重置密码 / 禁用用户 / 踢下线
    题目类  : 建题 / 改题 / 删题 / 看测试数据 / 导出题包 / 导入题包 / 发布题目
    数据类  : 上传数据 / 校验数据 / 生成数据 / 对拍 / 查看 std
    比赛类  : 建赛 / 开赛 / 延时补时 / 暂停 / 结束 / 封榜解封 / 动态改题
    评测类  : 提交 / 重测自己 / 重测他人 / 重测某题 / 取消评测 / 看评测详情
    社区类  : 发帖 / 回帖 / 写题解 / 答疑 / 私信 / 上传附件 / 删帖 / 置顶
    统计类  : 导出成绩 / 查看分析 / 导出代码
    系统类  : 改设置 / 备份 / 恢复 / 看审计日志 / 管理权限
    约束：所有权限校验必须在服务端完成；前端隐藏按钮只作体验优化，不构成安全边界。

2.3 账号安全
    - 密码使用 Argon2id（或 bcrypt cost≥12）哈希存储，绝不明文。
    - 登录失败按"账号 + IP"双维度限流（5 次/分钟，20 次/小时），超限锁定。
    - 会话使用 HttpOnly + SameSite=Lax 的 Cookie；可选"记住我"7 天。
    - 支持批量导入（CSV/Excel：考号/姓名/班级/初始密码/角色），导入前预览与冲突处理。
    - 支持邀请码/比赛码自助注册；支持管理员统一重置密码并强制首次登录改密。
    - 支持"考试模式"：同 IP/同浏览器多账号检测提示（仅提示，不自动封禁）。
    - 所有登录、改密、权限变更、重测、删数据操作写审计日志（不可篡改追加）。

4. 功能需求
--------------------------------------------------------------------------------
4.1 账号与认证（FR-ACC）
  FR-ACC-001 [P0] 账号密码登录、退出；会话超时（默认 8 小时，可配）。
  FR-ACC-002 [P0] 管理员创建/编辑/禁用账号；批量导入 CSV/Excel（字段映射可视化预览）。
  FR-ACC-003 [P0] 角色与权限点管理；按比赛授予临时权限（如某场比赛的重测权）。
  FR-ACC-004 [P0] 首次登录强制改密（可开关）；管理员重置密码并生成随机初始密码。
  FR-ACC-005 [P1] 邀请码/比赛码注册；注册审核队列（可自动通过）。
  FR-ACC-006 [P1] 个人资料（昵称/班级/头像可选）；在线状态与最后活跃时间。
  FR-ACC-007 [P1] 登录审计：时间、IP、UA、结果；异地/多端登录提示。
  FR-ACC-008 [P1] 账号导出（成绩单/账号表）；敏感字段脱敏。
  FR-ACC-009 [P2] 二次验证（TOTP）用于管理员账号（可开关）。
  FR-ACC-010 [P2] 单点并发登录限制（同账号仅 1 个活跃会话，可配）。

4.2 题库与题目（FR-PRB）
  题型：
  FR-PRB-001 [P0] 传统题：标准输入/标准输出。
  FR-PRB-002 [P0] 文件 IO 题：可配置输入输出文件名（如 problem.in/problem.out），
                  或"自动探测"（数据文件名推断）。两种模式题面自动生成说明。
  FR-PRB-003 [P0] 交互题：Interactor 与选手程序双向管道通信（testlib registerInteraction）。
  FR-PRB-004 [P1] 提交答案题（Output-only）：选手上传答案文件，系统按测试点比对。
  FR-PRB-005 [P1] 客观题：单选、多选、判断、填空；答案与解析由出题人配置。
  FR-PRB-006 [P2] 多文件提交题（工程题）：指定文件清单与入口，整体打包评测。

  题目属性：
  FR-PRB-010 [P0] 题目 ID、标题、难度（洛谷式 1~8 级或自定义）、标签、来源。
  FR-PRB-011 [P0] 时限（ms）、内存（MB）、语言限制、编译选项（C++ 标准/O2）。
  FR-PRB-012 [P0] 题面 Markdown + KaTeX 公式 + 图片附件；样例输入/输出/解释。
  FR-PRB-013 [P0] 测试点：数据文件列表、分值、子任务分组、测试点依赖（可配）。
  FR-PRB-014 [P0] 比较方式：内置（逐字节/忽略行尾空白/忽略全部空白/浮点误差/忽略大小写）
                  或 SPJ（testlib / Lemon 六参数）。
  FR-PRB-015 [P0] 题目可见性：公开 / 仅比赛内 / 指定用户可见 / 隐藏；禁止赛中提前泄露。
  FR-PRB-016 [P1] 题目版本历史：保存配置与题面快照，可回滚；变更记审计。
  FR-PRB-017 [P1] 题目复制/克隆；跨比赛复用（引用同一题目或快照）。
  FR-PRB-018 [P1] 题包导入导出：自定义 JSON + 数据目录打包 zip；导入前预检与冲突处理。
  FR-PRB-019 [P1] 兼容导入模板：Lemon/LemonLime 目录、CSP 题包、Cena 目录、通用
                  "目录 + in/out 文件"；模板可视化配置（目录层级、文件命名正则）。
  FR-PRB-020 [P1] 题目收藏、错题本、按标签/难度/通过率筛选与搜索。
  FR-PRB-021 [P2] 题目推荐（按标签/难度/未通过题）；每日一题（可开关）。
  FR-PRB-022 [P2] 题目讨论区/题解区（见 4.6）；题解审核与赛后可见策略。
  FR-PRB-023 [P1] 数据完整性：MD5/SHA-256 校验、缺失/多余文件检测、编码检查（UTF-8/CRLF）。
  FR-PRB-024 [P0] 数据上传：单文件 ≤64MB（可配），单题 ≤4GB（可配），分片上传，
                  断点续传；上传后自动校验与预览前 100 行。
  FR-PRB-025 [P1] 软删除与回收站：删题先入回收站，可恢复；彻底删除需二次确认。

4.3 评测内核（FR-JDG）
  提交与队列：
  FR-JDG-001 [P0] 提交源码（≤256KB，可配），按题目语言限制校验扩展名。
  FR-JDG-002 [P0] 评测队列：SQLite 持久化任务，支持优先级（赛中 > 练习 > 重测）、
                  用户公平轮转（单个用户不会霸占全部评测位）、并发数可配。
  FR-JDG-003 [P0] 评测并发默认 = min(2, 物理核数-1)，4 核主机默认 2 个评测位、最多 3 个
                  （可配）；满载时前端显示排队位置。
  FR-JDG-004 [P0] 任务状态机：queued → compiling → running → finished/failed/canceled。
  FR-JDG-005 [P0] 取消评测（权限控制）；取消后释放进程与临时目录。
  FR-JDG-006 [P0] 崩溃恢复：程序重启后自动恢复 queued/running 任务（running 重跑）。
  FR-JDG-007 [P0] 重复提交限流（默认同用户同题 10 秒冷却，可配）；429 友好提示。
  FR-JDG-008 [P1] 编译缓存：按源码哈希复用编译产物（相同代码重复提交、重测）。
  FR-JDG-009 [P1] 评测优先级插队与"评测窗口"（比赛期间暂停练习评测，可配）。

  编译：
  FR-JDG-010 [P0] C/C++ 编译命令模板可配（默认 g++ -O2 -std=c++17 -static？不强制静态）。
  FR-JDG-011 [P0] 编译超时（默认 15s）、编译输出保留（截断至 64KB）、CE 展示诊断信息。
  FR-JDG-012 [P0] Python3 可选：解释执行、时限倍率（默认 2x，可配）、内存口径说明。
  FR-JDG-013 [P1] 编译器版本探测与健康检查；未配置时禁止开赛并引导安装。
  FR-JDG-014 [P2] 自定义语言（配置文件：编译命令、运行命令、源码扩展名、时限倍率）。

  沙箱与资源：
  FR-JDG-020 [P0] Windows Job Object：内存上限、进程数上限、KILL_ON_JOB_CLOSE、
                  超时杀进程树；受限令牌（去管理员组）运行。
  FR-JDG-021 [P0] CPU 时间（用户+内核）判定；墙钟上限 = max(2×时限, 时限+2s)；
                  超墙钟强制终止并记 TLE/RE（可配）。
  FR-JDG-022 [P0] 内存峰值统计（Job Object/工作集采样，10ms 粒度）；超限即 MLE。
  FR-JDG-023 [P0] 独立临时工作目录，评测后清理；路径不含中文/空格（内部短路径）。
  FR-JDG-024 [P0] 标准输入输出重定向到文件；stdout/stderr 大小上限（默认 64MB，OLE）。
  FR-JDG-025 [P0] 清理环境变量，仅保留最小集合（PATH/TEMP 等），禁止继承敏感变量。
  FR-JDG-026 [P1] 限制子进程数量（默认 1，Python/多线程题可配）；检测 fork 炸弹。
  FR-JDG-027 [P1] 运行目录 ACL 收紧：选手进程不可读取题目的标准答案/其他选手代码
                  （在工程级沙箱能力内尽力而为，残余风险在文档中声明）。
  FR-JDG-028 [P2] 可选 WSL2/独立 Linux 评测后端（go-judge，MIT）作为"强沙箱模式"。

  比较与判分：
  FR-JDG-030 [P0] 内置比较器：精确 / 忽略行尾空白 / 忽略所有空白 / 浮点（绝对+相对误差）
                  / 忽略大小写；PE 策略可配（严格/宽松）。
  FR-JDG-031 [P0] SPJ 双模式：
                  (a) testlib：registerTestlibCmd + inf/ouf/ans + quitf(_ok/_wa/_pe/_dirt)；
                  (b) Lemon 六参数：input、user_out、answer、full_score、score_file、info_file；
                  编译缓存、超时（默认 10s）、崩溃记 SE，score 越界截断并告警。

  FR-JDG-033 [P0] 部分分（PC）：SPJ 返回 0~100 分；总分 = 各点/各子任务聚合。
  FR-JDG-034 [P0] 交互题评测：Interactor 与选手双向管道，协议错误/超时判 PE 或 WA；
                  交互日志截断保存供复盘。
  FR-JDG-035 [P1] 提交答案题：按测试点读取选手上传文件；支持文件夹或多文件映射。
  FR-JDG-036 [P1] 客观题判分：单选全对得分；多选漏选按比例/固定部分分（可配），
                  错选 0 分；判断二值；填空支持多答案、忽略大小写/空白、可选正则；

5. 非功能需求
--------------------------------------------------------------------------------
5.1 性能（关键约束，设计第一优先级）
  性能是硬约束：目标主机只有 4 核 / 8GB / SSD，却要承载 300 在线、峰值 50 人同时
  提交。任何功能设计必须先通过"性能预算"，否则优化或降级，不允许"先做完再优化"。

5.1.1 硬件与容量基线
  - 主机：4 核 CPU、8GB 内存、SSD（≥50GB 可用）、1000M 局域网。
  - 规模：500 注册 / 300 同时在线（活跃会话）/ 峰值 50 并发提交；
    单场 3~8 题、单题 10~30 测试点、单场提交 ≤15000 次。
  - 评测并发默认 min(2, 物理核数-1)，即 4 核时 2 个评测位；最多 3 个（可配，
    超过 2 时 Web 指标降级为"尽力而为"）。

5.1.2 资源预算（300 在线 + 50 并发提交稳定运行）
  - 进程总内存 ≤ 900MB（Electron 渲染 ≤ 350MB、主进程/服务 ≤ 350MB、
    SQLite page cache ≤ 64MB、评测缓冲/临时 ≤ 128MB）。
  - 空闲 CPU ≤ 5%；混合负载（评测 + Web）平均 ≤ 80%，不出现持续 100%。
  - 磁盘：评测临时目录同时占用 ≤ 2GB；WAL ≤ 256MB；日志滚动总量 ≤ 1GB。
  - 网络：LAN 单请求 payload ≤ 200KB；榜单单次推送 ≤ 50KB。
  - 连接：300 个 WebSocket + HTTP keep-alive；进程句柄 ≤ 2000；心跳 30s。

5.1.3 性能指标（P0 验收线）
  NFR-PERF-01 首屏（冷）≤ 1.5s；二次访问 ≤ 500ms；路由切换 ≤ 100ms。
  NFR-PERF-02 常规 API p95 ≤ 150ms、p99 ≤ 400ms（300 在线、50 QPS 混合负载）。
  NFR-PERF-03 WebSocket 推送 ≤ 700ms；断线重连 ≤ 2s；心跳不造成抖动。
  NFR-PERF-04 榜单增量更新 ≤ 1s；500 人 × 8 题全量重算 ≤ 300ms。
  NFR-PERF-05 评测任务启动开销 ≤ 150ms；单测试点框架开销 ≤ 40ms。
  NFR-PERF-06 2 个评测位、20 个 1s 测试点：单提交总评测 ≤ 25s；吞吐 ≥ 80 点/分钟；
             50 个同类提交（1000 点）≤ 15 分钟消化完（含编译）。
  NFR-PERF-07 50 并发提交：选手 3s 内看到"排队中/排第 N 位"；任务零丢失、可取消。
  NFR-PERF-08 SQLite WAL；写事务批量提交；读不阻塞；无 N+1；慢查询 >50ms 记录。
  NFR-PERF-09 300 在线时总内存 ≤ 900MB；事件循环阻塞单次 ≤ 50ms。
  NFR-PERF-10 冷启动 ≤ 4s（空库 ≤ 2.5s）；退出 ≤ 2s。
  NFR-PERF-11 前端首包 gzip ≤ 400KB；路由级分包；首屏关键 CSS 内联。
  NFR-PERF-12 1GB 题包上传 ≤ 90s；上传流式/分片，不整包入内存。
  NFR-PERF-13 评测数据流式读写；大文件不整读内存；输出超限截断。
  NFR-PERF-14 300 并发登录/榜单压测：错误率 < 0.1%，无 5xx，无超时雪崩。
  NFR-PERF-15 编译缓存命中（重测/重复提交）≥ 80% 时，评测平均耗时降 ≥ 40%。
  NFR-PERF-16 15 万提交、500 用户、50 题规模下，列表页 p95 ≤ 200ms。

5.1.4 强制优化约束（架构与实现红线）
  A. 服务端
    1) SQLite：WAL + synchronous=NORMAL + 预编译语句 + 事务批量写；高频查询
       必须有覆盖索引；禁止 SELECT *；分页用 keyset 而非 OFFSET。
    2) 榜单：事件驱动增量更新 + 内存快照；禁止每次请求全表扫描；封榜只影响
       展示层，不触发重复计算。
    3) 统计：通过率/AC 数/首杀等异步聚合落表（提交后队列或定时），请求只读结果。
    4) 事件循环：禁止同步文件 IO/大 JSON/哈希/压缩阻塞主线程；CPU 密集与文件
       操作放 worker_threads 或子进程。
    5) HTTP：keep-alive、ETag/304、gzip/brotli、静态资源强缓存（hash 文件名）；
       API 字段裁剪；高频批量接口合并（榜单、题目列表）。
    6) WebSocket：紧凑 JSON/二进制、增量 delta、按比赛/页面分房间；避免全量广播；
       慢消费者丢弃中间帧只发最新快照。
    7) 评测：任务/结果批量落盘；stdin/stdout 用文件句柄而非内存；编译缓存按源码
       哈希；临时目录复用并定期清理；子进程启动参数最小化。
    8) 日志：异步批量写；生产级别 info；禁止每请求同步写盘。
  B. 前端
    1) 路由级代码分割；Monaco 懒加载；图标按需引入；字体本地子集。
    2) 长列表虚拟滚动（提交/记录/榜单）；表格默认分页 50 条。
    3) 榜单/题面缓存 + 乐观更新；WS 增量合并，避免整页重渲染。
    4) 组件 memo/selector；避免大对象 context；搜索/滚动防抖节流。
    5) 图片懒加载；首屏骨架屏，避免布局抖动。
  C. 启动与安装
    1) 启动只做必要初始化；题库/榜单懒加载；数据库迁移后台执行且可恢复。
    2) 编译器按需安装；首次启动不阻塞 UI。

5.1.5 性能门禁
  - 每期交付前跑压测：300 在线浏览、50 并发提交、榜单刷新、封榜切换、登录洪峰。
  - 指标回归 >10% 视为不通过；性能预算超标的功能必须优化或降级。
  - 压测脚本、基准数据、火焰图与慢查询报告随仓库交付（验收方法见 8.3）。

5.2 可靠性
  NFR-REL-01 崩溃恢复：数据库事务保证一致性；queued/running 任务可恢复；提交不丢。
  NFR-REL-02 断电/强杀后重启：自动备份 + 完整性检查；损坏时给出恢复建议。
  NFR-REL-03 单题数据损坏不影响其他题目；评测失败隔离（SE）不阻断队列。
  NFR-REL-04 备份可验证（恢复演练脚本）；备份失败告警。
  NFR-REL-05 无网络依赖：除首次安装编译器外，核心功能完全离线可用。

5.3 安全
  NFR-SEC-01 所有接口鉴权与越权校验（IDOR 防护）；选手不能看他人代码/答案（按策略）。
  NFR-SEC-02 密码哈希、登录限流、会话安全、CSRF Token、XSS 转义、SQL 参数化。
  NFR-SEC-03 上传限制：类型白名单、大小、路径穿越防护、随机存储名、下载鉴权。
  NFR-SEC-04 选手代码只在服务器沙箱运行，浏览器不执行用户代码。
  NFR-SEC-05 审计日志追加写、可导出、不允许普通管理员删除。
  NFR-SEC-06 私信/论坛防骚扰：限流、黑名单、举报、禁言；敏感词可配。
  NFR-SEC-07 工程级沙箱的残余风险必须写入用户文档（可读同机文件、可联网等）。

5.4 兼容性与部署
  NFR-COM-01 Windows 10 1809+ / Windows 11 / Server 2019+ x64。
  NFR-COM-02 安装包（NSIS 或 Electron Builder），支持绿色版；卸载不删数据（需确认）。
  NFR-COM-03 端口冲突检测与自动建议；防火墙入站规则引导（需管理员权限时提示）。
  NFR-COM-04 浏览器：Chrome/Edge 100+、Firefox 100+；不支持 IE。
  NFR-COM-05 中文路径、空格路径、长路径（>260）兼容；数据目录可迁移。
  NFR-COM-06 高 DPI 缩放 100%~200% 布局正常。
  NFR-COM-07 HTTPS 可选：启用后浏览器/WS 均走加密通道；自签证书安装引导与风险提示。
  NFR-COM-08 4 核 8G 主机上安装不触发杀毒误报（签名可选）；安装/升级失败可回滚。

5.5 可维护性与可测试性
  NFR-MNT-01 模块化：Web 前端、HTTP/WS 服务、评测引擎、存储层边界清晰，可独立测试。
  NFR-MNT-02 评测引擎可在无 GUI 的 CLI 模式下运行（便于自动化测试与压测）。

  NFR-MNT-04 配置集中管理（类型校验 + 默认值 + 迁移）。
  NFR-MNT-05 日志带 requestId/submissionId，便于排查。

5.6 UI/UX（朴素但不难看）

  NFR-UX-05 比赛页信息层级：倒计时/公告/题目列表/我的提交/榜单，一屏可及。

7. 功能攻击（红队推演）
--------------------------------------------------------------------------------
说明：以下为"如果我是对手/倒霉老师，我会怎么搞坏它"，每条给出系统应对，并映射需求。

7.1 作弊与泄题
    A1 赛中提前看题/看他人代码 → 题面按时间开放；代码与测试数据按策略隐藏；
       封榜；访问控制；审计。
    A2 抄同学代码 → 本期人工代码复核（按需导出某场全部源码）+ 赛后代码开放策略 +
       提交时间/相似模式的人工排查；自动查重不在本期（见 4.7、10.Q3）。
    A3 猜测试点骗分（输出常量）→ 题面样例有限；数据保密；SPJ/多组数据；
       隐藏测试点；赛后复盘。
    A4 用 std/数据文件作弊 → 运行目录隔离；数据目录 ACL 收紧（FR-JDG-027）；
       禁止提交答案题读取答案目录；审计可疑进程（尽力而为）。
    A5 多账号刷榜 → 考号唯一；同 IP 多账号提示；报名名单绑定；审计。
    A6 赛中私聊传答案 → 私信默认受限、限流、审计、举报；赛中论坛关闭。

7.2 恶意/异常代码
    B1 死循环 → CPU 时限 + 墙钟双保险；杀进程树。
    B2 内存炸弹 → Job Object 内存上限；超限 MLE；杀进程。
    B3 fork 炸弹/多进程 → 进程数上限；Job Object KILL_ON_JOB_CLOSE。
    B4 输出炸弹 → stdout 文件大小上限（OLE），流式截断；磁盘配额检查。
    B5 读文件/写文件/删文件 → 独立临时目录；受限令牌；ACL 收紧；评测后清理；
       残余风险写入文档。
    B6 联网/外联 → 工程级沙箱不阻断（明确限制）；可选防火墙规则/强沙箱模式
       （FR-JDG-028）；赛后审计。
    B7 伪造评测结果 → 结果由服务端生成，选手端只读；签名/校验（可选）。
    B8 编译器漏洞利用 → 编译器只编译不运行；编译超时；编译输出截断。
    B9 提交超大源码 → 大小限制；语法检查；拒绝二进制/压缩炸弹。

7.3 误操作
    C1 删题/删赛/恢复备份 → 二次确认 + 输入确认词 + 自动备份 + 审计 + 软删除。
    C2 改时限/数据导致成绩不一致 → 版本快照 + 影响提示 + 重测入口 + 审计。
    C3 关程序/断电 → 崩溃恢复 + 自动备份 + 任务重排队。
    C4 端口被占/防火墙拦截 → 启动自检 + 诊断中心 + 明确提示。
    C5 编译器路径错/版本旧 → 启动检查、比赛前拦截、引导安装。
    C6 误封选手/误封榜 → 操作可撤销 + 审计 + 二次确认。

7.4 资源与并发攻击
    D1 开赛瞬间 300 人刷新 → 静态缓存 + 限流 + 骨架屏 + 服务端分页。
    D2 50 人同时提交 → 队列 + 公平调度 + 排队位置展示 + 限流。
    D3 单用户疯狂提交 → 冷却 + 每分钟上限 + 429 + 审计。
    D4 长时间比赛大量提交 → 归档/分页/索引；统计异步聚合。
    D5 大屏/榜单高频轮询 → WebSocket 推送 + 增量更新。
    D6 大文件上传占满磁盘 → 配额检查 + 上传大小限制 + 磁盘告警。
    D7 评测进程卡死 → 硬超时 + 心跳 + 强制终止 + 任务重排。

7.5 数据损坏与安全
    E1 SQLite 损坏 → WAL + 完整性检查 + 自动备份 + 恢复向导。
    E2 题包损坏/缺文件 → 导入预检 + SHA-256 + 启动检查 + 明确报错。
    E3 XSS/CSRF → 转义 + CSP + CSRF Token + SameSite。
    E4 路径穿越/任意文件读 → 上传随机名 + 白名单 + 路径规范化校验。
    E5 越权看数据/改分 → 服务端鉴权 + 权限点 + 审计 + 二次确认。
    E6 密码爆破 → 限流 + 锁定 + 强密码策略（管理员）。
    E7 私信骚扰/广告 → 限流 + 敏感词 + 举报 + 禁言 + 审计。
    E8 附件木马 → 白名单 + 大小限制 + 不执行 + 下载鉴权 + 提示。

7.6 赛事运营异常
    F1 比赛延时/提前结束 → 时间控制 + 审计 + 公告 + 榜单冻结。
    F2 题目出错/数据有误 → 赛中可禁用题目/重测/公告；成绩重算。
    F3 选手掉线/浏览器崩溃 → 自动重连 + 本地草稿（P2）+ 提交记录可查。
    F4 断网/主机休眠 → 桌面程序保持运行提示 + 网络自检 + 电源策略建议。
    F5 赛后申诉 → 申诉窗口 + 人工改分 + 审计 + 重新导出成绩。
    F6 多场比赛时间重叠 → 比赛隔离 + 调度优先级 + 资源提示。

7.7 红队推演产生的新增需求（已并入正文对应编号）
    - 提交草稿自动保存（FR-WEB-011）。
    - 比赛锁定与变更影响提示（FR-CST-017）。

    - 危险操作确认词与回滚点（FR-SYS-011）。

8.2 一期验收清单（Given/When/Then 摘要）
    V1 安装后首次启动完成初始化，检测到编译器缺失时给出可执行的安装引导。
    V2 创建一道 A+B 传统题，导入 10 个测试点与 SPJ，样例自测通过。
    V3 选手登录、提交错误代码，收到 WA 与测试点明细；提交死循环代码收到 TLE；
       提交大内存代码收到 MLE；提交语法错误收到 CE 诊断。
    V4 建一场 2 小时 OI 比赛，3 题，10 名选手并发提交，榜单实时正确；
       封榜后得分隐藏、解封后恢复。
    V5 比赛中强制结束进程并重启程序，已提交任务不丢失且能继续评测。
    V6 300 并发用户压测下页面可用、榜单正确、无 5xx。
    V7 500 人规模下 50 并发提交，队列有序、无任务丢失、错误率 < 0.1%。
    V8 导出成绩 CSV/Excel 与审计日志，数据与页面一致。
    V9 在 4 核 8G 主机上按 8.3 压测：API p95 ≤ 150ms、榜单增量 ≤ 1s、
       50 并发提交零丢失、总内存 ≤ 900MB。
    V10 交互题：选手程序与 interactor 正常对话并给出分数；超时/协议错误被正确判罚。

8.3 性能验收方法
    - 环境：4 核 8G + SSD 主机，1000M 局域网；评测并发按默认 2。
    - 提供压测脚本（模拟 300 在线：登录、刷题面、看榜单、提交）。
    - 指标采集：API p95/p99、WS 延迟、榜单更新时延、评测吞吐、内存/CPU。
    - 场景：开赛瞬间刷新、50 并发提交、封榜瞬间、全量榜单页、登录洪峰。
    - 通过线：第 5.1 节指标全部达标；未达标则一期不算完成。

8.4 安全验收
    - 越权测试：选手访问管理 API、他人代码、测试数据均被拒绝。
    - 输入测试：XSS/CSRF/路径穿越/超大上传/恶意扩展名被拦截。
    - 沙箱测试：死循环、内存炸弹、fork 炸弹、输出炸弹、读写工作目录外文件
      （记录实际行为与残余风险）。
    - 登录测试：爆破限流、会话过期、强制改密生效。

10. 已确认问题与结论（2026-10-31 评审）
--------------------------------------------------------------------------------
  Q1 硬件：4 核 8G + SSD；性能预算与指标按此收紧（见 5.1）。
  Q2 容量：单题数据 ≤4GB、单场提交 ≤1.5 万；上限可配置。
  Q3 查重：本期不做；仅提供源码批量导出，预留数据模型（见 4.7、9.O9）。
  Q4 可见性：赛中对选手隐藏测试数据与 std；赛后按比赛策略开放。
  Q5 HTTPS：默认 HTTP，可配置自签 HTTPS（FR-SYS-015）。
  Q6 班级：一期交付班级统计与导出（FR-RNK-013）。
  Q7 奖项：内置 3~5 个模板 + 可编辑规则（FR-RNK-009）。
  Q8 交互题：一期交付（FR-PRB-003）；提交答案题二期（FR-PRB-004）。
  Q9 客观题：赛中即时判分，按比赛可配赛后统一判（FR-JDG-036）。
  Q10 题解：管理员/出题人可直接发布；其他角色投稿需审核（FR-COM-003/011）。
  以上为评审基线；变更需更新本文件并重新评审受影响章节。

附录 A 评测状态码
--------------------------------------------------------------------------------
  AC   通过（Accepted）
  WA   答案错误（包括比较器判定错误）
  TLE  超时（CPU 或墙钟上限）
  MLE  内存超限
  RE   运行时错误（非零退出、崩溃、异常信号）
  CE   编译错误
  OLE  输出超限
  PE   格式错误（Presentation Error，可配是否单独判定）
  PC   部分正确（Partial Correct，SPJ 给部分分）
  SK   跳过（依赖未通过等原因未运行）
  SE   系统错误（SPJ 崩溃、评测环境异常、判题器错误）
  UKE  未知错误（兜底，需保留日志）
  JUDGING/COMPILING/QUEUED 为进行中展示状态。

附录 B 评测协议
--------------------------------------------------------------------------------
  B.1 testlib 模式（首选）
    checker: registerTestlibCmd(argc, argv) 读取 inf/ouf/ans；
    使用 quitf(_ok/_wa/_pe/_dirt, ...) 或 quitp(score, ...) 给部分分。
    validator: registerValidation + inf，违规 exit 1 并输出原因。
    interactor: registerInteraction + tout/ouf；选手程序与 interactor 双向管道通信。
  B.2 Lemon 六参数模式（兼容）
    调用：checker input.txt user_out.txt answer.txt full_score score.txt info.txt
    约定：score.txt 写入 0..full_score 的分数；info.txt 写人类可读信息；
          退出码 0 表示运行成功；崩溃/超时记 SE；分数越界截断并告警。
  B.3 内置比较器模式
    逐字节 / 忽略行尾空白 / 忽略所有空白 / 浮点（abs+rel，eps 可配）/ 忽略大小写。
    默认忽略行尾空白与末尾换行；PE 是否单独判定可配。

12.6 性能约束（扩张功能必须遵守）
  - "实时"页面只允许 WS 增量，禁止 1s 轮询；监考视图按需订阅、只推可见列。
  - 统计/难度校准/推荐/奖牌线：异步预计算 + 缓存表，请求只读结果。
  - PDF/证书/大报表：后台任务，生成后下载，并发上限 1。
  - 样例自测：独立队列 + 严格限流，避免与正式评测抢占 2 个评测位。
  - 榜单快照/回放：只存聚合结果，单份 ≤200KB。
  - 题库/帖子搜索：FTS5 索引，禁止 LIKE '%x%' 全表扫描。
  - AB 卷：引用题目快照，不复制测试数据。
  - 新增页面必须路由分包；新增列表必须分页/虚拟滚动。

12.7 建议不纳入（候选池，除非另行评审）
  - AI 辅助出题/评分/语义查重（隐私、成本、不可控）。
  - 摄像头/人脸识别/切屏监控等考试监控硬件。
  - 在线 IDE 完整多语言编译链与任意代码运行（超出评测范围）。
  - 公网多租户、支付、直播。
  - 自动组卷算法（保留手工组卷 + 题单）。

12.8 验收
  - P1 扩展随二期验收，且不得导致 5.1 指标回退；新增页面/列表须满足性能红线。
  - P2 扩展按季度排期，逐项确认后再进入实现计划。
